# Product

## Register

product

## Users

Developers using Pincer inside a running browser preview. They are inspecting the page, selecting rendered elements, and giving a coding agent precise source context without leaving their current workflow.

## Product Purpose

Pincer connects visible UI to its source code so developers can reference an element, describe a change, and have an already-installed coding agent edit the real project. Success means selecting, copying, or sending a source reference is immediate, precise, and unobtrusive.

## Brand Personality

Focused, minimal, and technical. Sober but modern, with the quiet confidence and smoothness of tools such as Notion, Codex, and Linear rather than a visibly “tech-themed” aesthetic.

## Anti-references

Oversized floating controls, loud or novelty-first developer tooling, decorative sci-fi styling, glass-heavy surfaces, excessive shadows, and UI that competes with the host application. The launcher must not dominate the page.

## Design Principles

- Keep the developer in context; primary actions happen next to the element or within the existing panel.
- Make precision visible; source references and selection state should be clear before an action is taken.
- Stay out of the host application’s way; controls are compact, calm, and progressively disclosed.
- Prefer familiar interaction patterns over novelty so the tool disappears into the workflow.
- Give immediate, local feedback for every action without interrupting the task.

## Accessibility & Inclusion

Meet WCAG 2.2 AA. All actions must be keyboard accessible with visible focus, readable contrast, descriptive accessible names, and reduced-motion behavior when requested by the operating system.
